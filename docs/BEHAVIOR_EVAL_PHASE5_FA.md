# فاز ۵ — معیار ارزیابی رفتار واقعی ایجنت

**وضعیت این نسخه:** سناریوها، تست قرارداد کد و آماده‌سازی محیط Codex تکمیل شده‌اند. **هیچ پاسخ تولیدشده توسط LLM در این فاز داوری نشده است.** قبولی تست Python معادل پیروی مدل از دستورالعمل نیست.

## دو لایه تست که نباید اشتباه گرفته شوند

**لایه A — تست قطعی Python در CI:** اجرای `account_state.classify`، `catalog_guard/campaign_decision.decide`، `post_intake.intake`، `review_gate.assess` و `router_probe.route` با داده ساختگی؛ خروجی‌های ثابت و محدودیت تعداد فایل‌ها بررسی می‌شوند. این آزمون نمی‌سنجد که مدل در متن فارسی/انگلیسی واقعاً مخالفت می‌کند.

**لایه B — اجرای واقعی مدل، نیازمند اجازه جداگانه:** ابزار موجود `tools/run_agent_eval.py` فقط در حالت `--mode run --allow-model-usage`، با Codex CLI احرازهویت‌شده، پاسخ را تولید و ثبت می‌کند؛ این کار ممکن است اعتبار مصرف کند. برنامه خودش هیچ سناریویی را قبولی اعلام نمی‌کند.

```bash
# بدون مدل، بدون هزینه
python3 tools/run_agent_eval.py --mode prepare --fixtures tests/behavior --output /tmp/igbd-phase5-prep

# فقط با تصمیم و احرازهویت صریح مالک، یک سناریو (ممکن است هزینه داشته باشد)
python3 tools/run_agent_eval.py --mode run --fixtures tests/behavior \
  --case phase5_goal_conflict_en --allow-model-usage --output /tmp/igbd-phase5-live

# کل تست‌های قطعی
python3 -m unittest discover -s tests -v
```

## عدالت ارزیابی و محدودیت‌ها

`prompt.txt` فقط درخواست و اطلاعات ساختگی را دارد. `rubric.json` در پوشه هر سناریو، خارج از `workspace/` و دور از پرامپت مدل ذخیره می‌شود. داور پس از اجرای مدل باید متن واقعی، فایل‌های واقعاً خوانده‌شده در صورت قابل مشاهده‌بودن، تعداد سؤال‌های غیرضروری، نوع تصمیم، دلیل مخالفت و موارد ممنوع را بررسی کند.

برای هر سناریو ثبت کن: `model`، `skill_commit`، `tested_at`، پاسخ کامل، شواهد اقدام انجام‌شده یا انجام‌نشده، `PASS/FAIL/NEEDS_REVIEW`، نام داور، توضیح خطا. بدون بررسی انسانی، خروجی فقط `NOT_GRADED` است.

**نکته:** حتی یک متن شامل واژه `DO_NOT_PROMOTE` می‌تواند هم‌زمان جمله «همین حالا بخرید» داشته باشد. بنابراین یافتن کلمه کلیدی نه قبولی است و نه تضمین رفتار ایمن. دو اجرای یک مدل ممکن است متفاوت باشند؛ پیش از اطمینان عملی به نسخه، چند اجرای مستقل و بازبینی موارد مرزی لازم است.

## محدودیت‌های باز

- اجرای واقعی مدل، امتیازدهی انسانی آن و تحلیل حساسیت به صورت‌بندی سؤال هنوز `not-implemented` هستند.
- تصمیم مخالفت با تغییر هدف برند، ماهیت کیفی دارد؛ تست Python فقط ثابت می‌کند دو پست برای نتیجه‌گیری آماری کافی نیست، نه اینکه خود ایجنت حتماً محترمانه مخالفت خواهد کرد.
- آستانه‌های نمونه پیش‌فرض از سیاست برند هستند، نه قواعد اینستاگرام. واقعیت متغیر الگوریتم با این آزمون بازسازی نمی‌شود.
- داده‌های واقعی پیج، فایل‌های شخصی و توکن‌ها نباید در Git عمومی یا گزارش artifact آپلود شوند.

## سخت‌گیری جدید در ثبت قبولی داور

`tools/grade_agent_eval.py` بدون مدل و بدون شبکه کار می‌کند و فقط مسیرهایی را که صریحاً به آن داده شده می‌خواند. قالب پیش‌فرض با `reviewed_full_response=false` و `unclear` ساخته می‌شود و قابل قبولی نیست. پس از اجرای واقعی، داور باید همه معیارها و رفتارهای ممنوع را بررسی کند، برای معیارهای محقق‌شده نقل‌قول عینی از پاسخ بیاورد و نبود موارد ممنوع را با خواندن کل پاسخ تأیید کند. کد نیز SHA-256 متن پاسخ/پرامپت و شناسه سناریو را با رکورد اجرا تطبیق می‌دهد. متن تغییرکرده، اجرای ناموفق، داوری ناقص و هر مورد ممنوعِ مشاهده‌شده PASS نمی‌گیرد.
