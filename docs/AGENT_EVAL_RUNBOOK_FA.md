# راهنمای ارزیابی واقعی رفتار ایجنت — نسخه 0.7-dev

## چه چیزی تست شده و چه چیزی هنوز تست نشده؟

- **تست کد و بسته نصب:** با GitHub Actions اجرا می‌شود؛ شامل روتر، تصمیم محصول، Trial، اعتبار داده، کاتالوگ و نصب واقعی از طریق Skills CLI
- **تست چندبرندی مصنوعی:** پنج کسب‌وکار ساختگی فارسی/انگلیسی را از نظر تصمیم‌های قابل‌محاسبه بررسی می‌کند
- **تست پاسخ واقعی مدل:** ابزار اجرای آن نوشته شده، اما تا زمانی که کاربر عمداً یک Run را اجرا نکند و خروجی توسط انسان بررسی نشود، **نتیجه موفق ثبت نمی‌شود**

## اجرای رایگان، بدون اتصال مدل

از ریشه مخزن:

```bash
python3 tools/run_agent_eval.py --mode prepare --output /tmp/igbd-prepared
```

این کار ۱۰ سناریوی پایه را آماده می‌کند و `summary.json` می‌سازد؛ هیچ مدل یا API را صدا نمی‌زند.

## اجرای واقعی محلی با Codex CLI

Codex CLI باید نصب شده باشد و کاربر مستقلاً وارد حساب مجاز خود شده باشد:

```bash
python3 tools/run_agent_eval.py --mode run \
  --case fa_sold_out \
  --allow-model-usage \
  --output /tmp/igbd-live-results
```

این اجرا ممکن است از سهمیه یا اعتبار مدل استفاده کند. محدودیت هر اجرای پیش‌فرض: فقط یک سناریوی انتخاب‌شده، Sandbox فقط‌خواندنی، با داده ساختگی، بدون انتشار یا هزینه تبلیغات. خروجی را در `answer.txt`، `events.jsonl` و `record.json` می‌بینید. فایل‌های trace تضمین نمی‌کنند تمام فایل‌های خوانده‌شده ایجنت از روی آنها قابل تشخیص باشند.

## اجرای واقعی اختیاری از GitHub

در مخزن، تب **Actions** → **Manual Codex agent behavior eval (opt-in)** → **Run workflow** را انتخاب کن. شاخه باید `main` باشد و تنها یک سناریو انتخاب می‌شود. این گردش‌کار فقط وقتی کلید `OPENAI_API_KEY` به‌صورت Secret در مخزن تنظیم شده باشد اجرا می‌شود. بدون کلید، قبل از تماس با مدل متوقف می‌شود. هیچ workflow تست معمولی یا Pull Request از مدل پولی استفاده نمی‌کند.

**هشدار امنیتی:** کلید API نباید در پیام، کد، workflow، فایل نتیجه یا Git قرار گیرد. اجرای هر سناریو مصرف بالقوه دارد. خروجی آن فقط برای ارزیابی دستی ذخیره می‌شود، نه ادعای قبولی خودکار.

## Rubric ارزیابی انسانی

| سناریو | معیار اصلی |
|---|---|
| محصول ناموجود | رد روشن فروش جدید، دلیل و جایگزین معتبر؛ عدم تولید CTA گمراه‌کننده |
| برند بدون چهره | عدم پیشنهاد talking-head یا اجبار به فیلم‌برداری از فرد |
| دوربین نامعلوم | سؤال مستقیم و کوتاه درباره تمایل به حضور در تصویر، پیش از سناریوی فیلم‌برداری |
| کپشن ساده | متن آماده، کوتاه، بدون گزارش مدیریتی طولانی |
| درخواست ضعیف | مخالفت مستدل به‌جای تأیید بی‌دلیل |
| Trial با داده کم | `INSUFFICIENT_DATA` و ممنوعیت نتیجه‌گیری از ۱–۲ پست |
| ادعای قوانین Meta | ارجاع به سند معتبر و تاریخ‌دار، بدون وزن الگوریتم ساختگی |

برای هر سناریو **PASS / FAIL / NEEDS-REVIEW** همراه با دلیل، مدل، نسخه Skill، تاریخ، trace و پاسخ ذخیره کن. چک کلمات کلیدی در ابزار، صرفاً علامت هشدار است و نمی‌تواند کیفیت پاسخ یا درستی رفتار ایجنت را اثبات کند.

## نتیجه‌گیری

تا این لحظه **اجرا و داوری پاسخ زنده مدل انجام نشده**؛ خروجی موفق GitHub Actions فقط صحت تست‌های Python، نصب و آماده‌سازی fixture را اثبات می‌کند. در هر نسخه تغییر روتر، منطق فروش، Trial یا قواعد زبان، سناریوهای ثابت مجدداً باید اجرا و بازبینی شوند.
