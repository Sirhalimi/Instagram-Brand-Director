# چک‌لیست انتشار هر نسخه — Instagram Brand Director

1. **معماری:** روتر فقط یک ماژول اصلی را می‌خواند. برای درخواست ترکیبی حداکثر یک ماژول اضافه و برای ادعای سیاست اینستاگرام حداکثر یک فایل دانش. تعداد فایل‌ها را با `scripts/router_probe.py` و تست‌ها بسنج.
2. **زبان:** برای فارسی و انگلیسی تست واقعی کپی داشته باش؛ متن فارسی نباید امتیاز مبتنی بر Regex انگلیسی بگیرد. هر زبان آینده نیازمند فایل locale، registry، آزمون و بازبینی انسانی است.
3. **ساختار داده:** داده‌های واقعی برند را بیرون مخزن عمومی نگه دار. `brand.md`, `baseline.md` و `posts.csv` باید اعتبارسنجی شوند؛ بدون داده کافی، نتیجه‌گیری نه.
4. **سنجش Trial:** معیار حداقل ریچ، پست‌های مستقل قابل‌مقایسه، کل ریچ مبنا، تازگی داده و زمان ثبت را قبل از آزمایش اعلام کن. شکست در هر معیار → `INSUFFICIENT_DATA`، نه توصیه قطعی درباره الگو.
5. **حافظه یادگیری:** هیچ یادگیری از یک یا دو پست وارد `learnings.md` نشود؛ پس از تکرار معتبر هم تأیید انسانی لازم است و ابزار به‌صورت خودکار نمی‌نویسد.
6. **پروژه‌های آماده:** قبل از بازنویسی، نسخه upstream را بررسی کن. کپی دقیق و مجوز را حفظ کن. برای هر فایل source path، commit SHA، Git blob SHA، تاریخ بررسی و تاریخ ایمپورت را ثبت و در تست CI مقایسه کن.
7. **وضعیت قابلیت‌ها:** `references/implementation-status.json` را در هر نسخه اصلاح کن. کار تکمیل‌نشده صریحاً `not-implemented` است؛ ماژول اختیاری بودن به‌معنای اجراشدن نیست.
8. **پاسخ‌ها:** درخواست کپشن = کپشن آماده و توضیح کوتاه. تصمیم استراتژیک = یک تصمیم قطعی + دلیل + گزینه ردشده + اقدام + بازبینی.
9. **تست‌ها:** Unit، fixture رفتار، بسته نصب‌شونده و `npx skills add` باید در GitHub Actions موفق شوند. تست قطعی قرارداد معادل eval واقعی مدل نیست؛ eval مدل جدا گزارش شود.
10. **منابع Meta:** گزاره‌های رسمی را با تاریخ و منبع در `knowledge/instagram-rules.md` نگه دار؛ قوانین و تغییرات Meta را هفته‌ای (در صورت دسترسی) و دستورالعمل اسکیل را ماهانه بازبینی کن.

## دستور نصب تأییدشده

```bash
npx skills add Sirhalimi/Instagram-Brand-Director --skill instagram-brand-director -a codex -y
```

اتصال OAuth، Insights زنده، داده محصولات، انتشار، ارسال دایرکت، media adapters، paid ads adapters، eval واقعی ایجنت و سازگاری فراتر از fa/en همگی تا زمان پیاده‌سازی و تست واقعی **not-implemented** هستند.
